Added

- **`--regtest-pow-bits` fixes regtest difficulty.** `--regtest-pow-bits 0x1f7fffff` (conf `regtest_pow_bits`) makes every regtest block at height 1 and above expect those compact bits instead of the trivial `0x207fffff`, so a CPU miner no longer finds a block with every share. A block more than two spacings after its parent, which includes block 1 on a real clock, may still use the pow-limit bits, as in Core. Validation, `generate*`, `getblocktemplate` and the SV2 Template Provider all follow it. Regtest only; any other network, or bits that are zero, negative, overflowing or not harder than the pow limit, fail startup. A chain that already carries harder bits keeps them whatever the flag says, so a new value needs a fresh chain. This is not a Bitcoin Core option.
