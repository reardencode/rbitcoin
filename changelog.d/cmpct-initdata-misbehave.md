Fixed

- **Every compact block that fails Core's `InitData` checks disconnects the peer (Core #35321).** A `cmpctblock` with no short ids and no prefilled txs, more than `MAX_BLOCK_TX_COUNT` (100,000) txs, a prefilled null tx (no inputs and no outputs), or a prefilled index past 16 bits now disconnects, the same as an out-of-range prefilled index already did. This holds for a requested block and for an unsolicited one. Before, such a block got a `getdata` reply and the peer kept its score.
- **A `cmpctblock` decodes a prefilled null tx the way Core does.** Core reads version, an empty vin, flags 0, and locktime as a tx with no inputs and no outputs. rust-bitcoin rejected those bytes, so the message was dropped as unknown and the peer kept its score. That tx now decodes and fails the `InitData` check. No other message or tx decodes differently.
