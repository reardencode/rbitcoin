Fixed

- **Every compact block that fails Core's `InitData` checks disconnects the peer (Core #35321).** A `cmpctblock` with no short ids and no prefilled txs, or with a prefilled null tx (no inputs and no outputs), now disconnects, the same as an out-of-range prefilled index already did. This holds for a requested block and for an unsolicited one. Before, such a block got a `getdata` reply and the peer kept its score.
- **A `cmpctblock` decodes a prefilled null tx the way Core does.** Core reads version, an empty vin, flags 0, and locktime as a tx with no inputs and no outputs. rust-bitcoin rejected those bytes, so the message was dropped as unknown and the peer kept its score. That tx now decodes and fails the `InitData` check. No other message or tx decodes differently.
- **A `cmpctblock` past 16 bits is dropped with no score, as in Core.** More than 65,535 txs, or a prefilled index past 65,535, fails the decode, and the session ignores the message. Before, up to 100,000 txs reconstructed and asked for the missing txs.
